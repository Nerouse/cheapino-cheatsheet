Why redesign a keyboard at all?

The Cheapino is a split ergonomic board with 36 keys: three rows of five per hand, plus three thumb keys on each side. A full-size keyboard has about a hundred. Everything else — numbers, symbols, arrows, function keys, even the mouse — has to arrive some other way: layers, where holding a thumb key temporarily turns the whole keyboard into a different one.

The stock layout is perfectly fine for typing. It is not fine for work where every hour is spent inside Ctrl / Shift / Alt combinations — SQL editors, notebooks, dashboards, terminals. So the goals were simple to state and hard to hit:

  • Hands stay on the home row. No reaching for arrows, digits or function keys.
  • Nothing latches by accident. A layer should disappear the moment you let go, unless you deliberately keep it.
  • Combos are built, not duplicated. One sticky Ctrl beats a dozen pre-baked Ctrl+key keys.
  • The result is provable. Every change is generated by a script and checked before it is allowed near the keyboard.

One constraint shaped everything: the layout had to live in a .vil file loaded through Vial — no hand-written C keymap — with firmware changes only where Vial genuinely cannot do the job.

The journey, in five generations

Every layout in this project is kept in the repository — the dead ends included. They are the receipts.

Nov 13 · Generation 0

The board arrives — and the matrix trap

Stock Vial firmware flashed, first layout loaded. The first lesson was physical: the Cheapino's matrix does not match the way the keyboard looks. In the .vil the halves are swapped, and the left-hand columns run backwards — physical Q sits in matrix column 10, T in column 6. The first thumb mapping had ENTER and Shift on the wrong sides and produced a wall of “keycode deserialize” errors. The rule born that day: never hand-edit a .vil.

Nov 20 · Generation 1

Attempt one: pure hold

Three left-thumb keys, each a momentary layer. Simple and safe — release the thumb and the letters come back. But three triggers turned out to be one too many to remember, and the mouse layer sat behind the least comfortable thumb. The folder layouts/hold keeps this design for the record.

Nov 22 · Generation 2

Attempt two: hold-and-toggle

Tip a thumb key to latch a layer, hold it to peek — QMK tap-dance on two thumb keys, four layers. It read beautifully on paper and confused the hands in practice: latched layers stuck around, and keys with two personalities wrecked muscle memory. Generation 2 is also where build discipline appeared: layouts are now generated from the stock template by script, validated, and only then loaded.

Nov 24 · The scoreboard

Make it visible, then make the rules

This site started as a scoreboard: an app that renders any .vil layer by layer, shows the encoder's job on every layer, and makes layer keys clickable. Being able to see the layout exposed the rules that still govern it today: put navigation and the sticky modifiers on the same layer; never force a layer switch mid-operation; prefer one sticky Ctrl over a dozen pre-built Ctrl+key shortcuts.

Nov 25 · Generation 3 — final

The sticky layout

Two thumb holds and a set of one-shot modifiers, inspired by the Seniply school of small-keyboard design. NAV carries arrows under H J K L, cut/copy/paste under X C V, Windows actions on the right hand, and sticky Win/Ctrl/Alt/Shift on Q W E A. MOUSE and F-KEYS became toggles reached from NAV that the firmware clears the instant NAV is released. The knob got three modes, the board got layer-coloured LEDs, and the repository was rebuilt around the design: one folder per generation, scripted builds, a format validator, and 67 assertion checks. This is the layout on the keyboard today.

Six principles that survived every rewrite

Home row is home

A layer is cheaper than a reach. If a key needs your hand to travel, it belongs on a layer instead.

Hold to peek

Momentary layers mean release equals undo. Toggles exist only where staying is the point — a mouse mode, a scroll mode.

One-shot beats one-off

A sticky modifier applies to the next key and then forgets itself. Four sticky keys replace hundreds of pre-built combinations.

No mid-operation detours

Everything an operation needs lives on one layer. Arrows, selection, and Home/End are on NAV because you use them together.

Design for the work

Not a typing demo — a data workflow. Run queries with Ctrl+F5, snip screenshots with Win+Shift+S, switch desktops, cut and paste SQL without leaving the layer.

Prove it, don't vibe it

Every layout is generated from the stock template and must pass 67 assertions plus a format validator before it touches the keyboard.

How the system works

A layer is a whole alternative keyboard hiding underneath this one. While you hold a layer thumb key, the keys send different actions; let go and the letters return. The six layers of the final layout:

BASEalways onType — QWERTY, hands never leave the home row
NUMBERS + SYMBOLShold left thumb middleSymbols on the left hand, a numpad on the right
NAVhold left thumb outerArrows, sticky modifiers, editing and Windows shortcuts
MOUSEon NAV: tap FPointer, clicks and wheel under the right hand
SCROLLtap the knobNo key changes — the knob becomes a horizontal scroll wheel
F-KEYSon NAV: tap DF1–F12, mirroring the number positions

Sub-layers clean up after themselves. Plain Vial cannot reliably nest toggles — a latching layer stays latched after its parent is released. A short firmware patch in keymap.c clears MOUSE and F-KEYS the moment NAV goes away, so the worst failure mode of a small keyboard simply cannot happen.

The knob has three jobs. Scroll up/down on BASE, media next/previous track on the layers, and scroll left/right once SCROLL is on. Pressing it is a real key too — a toggle in the corner of the matrix.

The LEDs are a legend. The patched firmware lights the underglow in the colour of the layer you are on — yellow for numbers, purple for NAV, cyan for mouse, red for F-keys — at 75% brightness so it informs instead of blinding. This site uses the same colours, and hovering any key shows its full explanation.

Nothing is hand-waved. The pipeline is: script/build_sticky.py generates the .vil from the stock template → validate_vil.py and check_positions.py check format and every switch position → scenario_sim.py runs 67 behavioural assertions → the file is loaded through Vial. Only then does it earn a place on the board.

Standing on shoulders

  • tompi/cheapino — the board itself: 36 keys, an RP2040, one encoder, and a matrix that keeps you honest.
  • getreu/vial-config-musclememory-cheapino2 — the number layout that seeded the numbers hand.
  • drinduka383/split-keyboard-layout — the symbol layout that seeded the symbols hand.
  • Seniply — the small-keyboard school that made one-shot modifiers the obvious answer.
  • Vial & QMK — configuration layers and the firmware hooks that make sub-layer clean-up and layer LEDs possible.

The community layouts that inspired this design are kept on disk in layouts/reference/, with their provenance notes, so every key can be traced back to where it came from.
